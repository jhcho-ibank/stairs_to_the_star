# 별까지 계단 — 회사 리더보드 에디션 🐈⭐

팀즈(Microsoft 365) 계정으로 로그인하고, 동료들의 최고 기록이 **그 계단 위에
프로필 사진 + 이름 깃발**로 꽂히는 사내 경쟁 버전.

```
stairs_to_the_star/
├── server.js            # 사내/로컬 서버 (Node 18+, 외부 패키지 없음)
├── api/                 # Vercel 서버리스 함수 (같은 lib/api.js를 씀)
│   ├── config.js
│   ├── leaderboard.js
│   └── score.js
├── lib/
│   ├── api.js           # 인증·점수·순위 로직 (공용)
│   └── store.js         # 저장소 어댑터 (KV / 파일 / 메모리)
├── public/
│   └── index.html       # 게임 (로그인·순위표 포함, 외부 스크립트 없음)
├── config.example.json  # config.json으로 복사해서 사용
├── vercel.json
├── scores.json          # 점수 저장 (자동 생성, git 제외)
├── .secret              # 순위표 익명 ID용 키 (자동 생성, git 제외)
└── README.md
```

**외부 라이브러리를 전혀 쓰지 않습니다.** 로그인(OAuth2 Authorization Code +
PKCE)도 브라우저 기본 기능만으로 직접 구현되어 있어, 받아야 할 파일이 없습니다.

## 지금 상태

`config.json`에 테넌트/클라이언트 ID가 입력되어 있고 `devFakeAuth`는 꺼져 있습니다.
남은 것은 **2-1의 SPA 플랫폼 등록 확인**과 **3 (HTTPS 배포)** 뿐입니다.

## 1. 실행

```bash
node server.js
```

`http://localhost:8443` 접속.

## 2. 팀즈(Entra ID) 로그인 연결

### 2-1. Azure 앱 등록 — 플랫폼 확인 필요

앱 ID는 이미 config.json에 들어가 있습니다. 포털에서 **인증(Authentication)**
화면을 열어 **플랫폼 구성**을 확인하세요.

- 박스 제목이 **"단일 페이지 애플리케이션"** 이어야 합니다.
  **"웹"** 으로 되어 있으면 토큰 교환이 CORS로 차단되어 로그인이 실패합니다.
  (매니페스트의 `replyUrlsWithType`에서 `"type": "Spa"` 인지로도 확인 가능)
- 플랫폼이 하나도 없으면 **"플랫폼 추가" → "단일 페이지 애플리케이션"** 을 고르고
  리디렉션 URI를 입력하세요. 테스트용으로 `http://localhost:8443/` 를 먼저 넣고,
  배포 후 `https://실제주소/` 를 추가하면 됩니다. (localhost는 HTTPS 예외)
- 리디렉션 URI는 **주소의 루트**여야 합니다. 게임은 항상 `origin + '/'` 를
  사용하므로 `/index.html` 같은 하위 경로로 접속해도 루트 하나만 등록하면 됩니다.
- API 사용 권한: Microsoft Graph `User.Read`(위임) — 이름·프로필 사진용

### 2-2. 로그인 동작 방식 (참고)

라이브러리 없이 표준 흐름을 직접 구현했습니다.

- **첫 방문 시 비밀번호 없이 자동 로그인 시도**: `prompt=none`으로 한 번
  조용히 인증합니다. 팀즈·Office에 이미 로그인된 PC나 Entra 가입 기기라면
  화면 전환 없이 바로 로그인됩니다. 세션이 없으면 즉시 되돌아와 로그인
  버튼을 보여주며, 리다이렉트 루프를 막기 위해 세션당 한 번만 시도합니다.
- 로그인 버튼 → PKCE 코드 생성 후 Microsoft 로그인 페이지로 이동
- 돌아오면 인가 코드를 토큰으로 교환 (state·nonce 검증 포함)
- 토큰은 localStorage에 보관하고, 만료 전 리프레시 토큰으로 조용히 갱신
  (Entra SPA 기준 약 24시간 슬라이딩)
- 마지막 계정을 `login_hint`로 넘겨 계정 선택 화면을 건너뜁니다.
  로그아웃하면 힌트를 지워 다른 계정으로 로그인할 수 있습니다.
- 서버는 받은 ID 토큰의 서명·발급자·대상·테넌트를 직접 검증합니다

> **로그아웃 동작**: 이 게임에서만 로그아웃하고, 브라우저의 회사 계정 세션은
> 건드리지 않습니다. Microsoft 로그아웃 페이지로 보내면 Outlook·Teams 웹까지
> 함께 로그아웃되어 다시 들어올 때 비밀번호를 새로 입력해야 하기 때문입니다.
> 계정 정보를 기억해 두므로 다시 로그인할 때 계정 선택 화면 없이 한 번에
> 들어갑니다. (다른 계정으로 바꾸려면 브라우저의 사이트 데이터를 지우세요.)

> **자동 로그인이 안 되는 경우**: 브라우저에 Microsoft 세션이 없으면
> (모바일에서 팀즈 앱은 로그인되어 있지만 Safari로 링크를 연 경우 등)
> 자동 로그인이 되지 않습니다. 이때는 버튼을 한 번 누르면 되고, 이후에는
> 24시간 동안 유지됩니다. 팀즈 안에서 링크를 열면 세션을 공유할 가능성이
> 높습니다.

> **리디렉션 URI 등록 확인 방법**: 배포 주소를 열었을 때 주소창이 그대로
> 돌아오면 등록된 것입니다. 등록되지 않았다면 `login.microsoftonline.com`
> 화면에 `AADSTS50011` 오류가 뜬 채 멈춥니다.
> (`curl`로 authorize URL을 찔러보는 방식은 소용없습니다 — Entra는 이 단계에서
> URI를 검사하지 않아 등록되지 않은 주소도 로그인 페이지가 정상적으로 뜹니다.)

## 3. Vercel 배포

`stairs-to-the-star.vercel.app` 로 배포하는 경우입니다. 정적 게임은 `public/`,
API는 `api/` 서버리스 함수로 자동 인식됩니다.

### 3-1. 프로젝트 연결

Vercel 대시보드 → **Add New… → Project** → 이 GitHub 저장소를 선택 →
프로젝트 이름을 **`stairs-to-the-star`** 로 지정(그래야 도메인이 맞습니다) → Deploy.

### 3-2. 환경변수 (Settings → Environment Variables)

| 이름 | 값 |
|---|---|
| `TENANT_ID` | 디렉터리(테넌트) ID |
| `CLIENT_ID` | 애플리케이션(클라이언트) ID |

`config.json`은 git에 올라가지 않으므로 Vercel에서는 이 두 개가 필수입니다.

### 3-3. 저장소 연결 — **이걸 안 하면 순위가 저장되지 않습니다**

Vercel 서버리스는 파일 쓰기가 불가능하고 인스턴스도 매번 바뀝니다.
저장소를 붙이기 전까지는 **메모리 모드**로 동작해서, 점수가 잠깐 보였다가
사라지고 사람마다 다른 순위가 보입니다.

Vercel 대시보드 → **Storage → Create Database → Upstash for Redis** 를 만들고
프로젝트에 연결하세요. 연결하면 `KV_REST_API_URL` / `KV_REST_API_TOKEN`
환경변수가 자동으로 주입되고, 코드가 알아서 그 저장소를 씁니다(무료 티어로 충분).

### 3-4. Azure 리디렉션 URI 추가

앱 등록 → 인증 → 단일 페이지 애플리케이션에
`https://stairs-to-the-star.vercel.app/` 를 추가하세요. (배포 도메인마다 필요)

### 3-5. 알아두실 것

- **공개 인터넷에 열립니다.** 로그인은 회사 테넌트로 제한되지만, 직원 이름과
  프로필 사진이 외부 클라우드(Vercel/Upstash)에 저장됩니다. 사내 정책상
  문제가 될 수 있으면 아래 "사내 서버 배포"를 쓰세요.
- Vercel 프리뷰 배포는 매번 다른 도메인이 생기는데, 그 도메인은 Azure에
  등록되어 있지 않아 로그인이 실패합니다(운영 도메인에서만 로그인 가능).

## 4. 사내 서버 배포

- **HTTPS 필수**: Microsoft 로그인은 `http://localhost` 외에는 HTTPS에서만
  동작합니다. 사내 리버스 프록시(IIS/nginx)에 인증서를 붙이고, 그 주소를
  Azure 앱 등록의 리디렉션 URI에 넣으세요.
- **프록시 뒤에 둘 때**는 config.json에 아래를 설정하세요.
  ```json
  { "bind": "127.0.0.1", "trustProxy": true }
  ```
  - `bind`: 평문 HTTP 포트가 사내망에 그대로 열리지 않도록 프록시만 접근 가능하게 제한
  - `trustProxy`: 요청 제한이 프록시 IP 하나로 뭉뚱그려지지 않도록 `X-Forwarded-For` 사용
    (프록시가 이 헤더를 **덮어쓰도록** 설정되어 있어야 합니다. 그렇지 않으면
    클라이언트가 헤더를 위조해 요청 제한을 우회할 수 있습니다.)
- **아웃바운드**: 서버가 토큰 검증용 공개키를 받으려면 `login.microsoftonline.com`
  에 나갈 수 있어야 합니다. 프록시를 거쳐야 한다면:
  ```bash
  HTTPS_PROXY=http://프록시:포트 node server.js
  ```
  (config.json의 `httpsProxy`로도 지정 가능. 서버가 CONNECT 터널로 처리합니다.)
- **팀즈에서 쓰기**: 채널 탭 추가 → "웹 사이트" 탭으로 게임 주소를 걸면 됩니다.
  팀즈 탭은 iframe이라 리다이렉트 로그인이 막히므로, 게임이 자동으로 감지해
  **팝업 로그인**으로 전환합니다. 사용자에게 팝업 허용이 필요할 수 있습니다.
  (가장 문제가 적은 방법은 채널에 그냥 **링크를 공유**하는 것입니다.)

## 5. 보안·프라이버시 설계

- 점수 제출과 **순위표 조회 모두 로그인이 필요**합니다. 사내 이름·사진 명부가
  비인증 요청에 노출되지 않도록 한 조치입니다.
- 순위표에는 Entra 계정 GUID(oid) 대신 서버가 HMAC으로 가린 익명 ID만 나갑니다.
  키는 `.secret`에 저장되며, 이 파일이 바뀌면 식별자가 전부 바뀝니다(순위 데이터는 유지).
- `devFakeAuth`(가짜 로그인)는 테스트 전용이며, **tenantId/clientId가 설정된
  서버에서는 코드 레벨에서 무시**됩니다. 켜져 있어도 `127.0.0.1`에만 바인딩됩니다.
- 프로필 사진은 형식·디코딩 크기(24KB)를 검사해 저장합니다.
- **점수 신뢰성**: 클라이언트 게임이라 작정한 조작까지는 막지 못합니다(재미용 앱 기준).
  서버는 토큰 검증, 점수 상한(100,000), 요청 제한(쓰기 30/분, 읽기 120/분)까지만 합니다.

## 6. 운영

- 점수 초기화: 서버 중지 후 `scores.json` 삭제
- 서버 이전/백업: `scores.json` + `.secret` 를 함께 옮기세요
- 종료 시 미저장 점수는 SIGINT/SIGTERM에서 자동 저장됩니다
- 사진이 쌓이면 순위표 응답이 커집니다. 인원이 많아지면 사진 저장을 끄거나
  더 작은 크기로 낮추는 것을 고려하세요 (`MAX_PHOTO_BYTES`)

## 7. 게임에서 보이는 것

- 동료의 최고 기록 계단에 **깃발(프로필 사진+이름+점수)** — 오르다 보면 실제로
  그 계단을 지나며 추월하게 됩니다. 내 깃발은 금색
- 점수 아래 **추격 칩**: 다음으로 잡을 동료와 남은 계단 수
- 시작 화면 TOP 5 / 게임오버 화면 TOP 10 + 내 순위(전체 기준)
